# GNSSjamLoc

GNSSjamLoc is a localization tool for intentional 
interfence sources (jammers), that are potentially disturbing
ligitimate signal reception (e.g. GPS). Given a dataset of power
field measurement associated with spatial coordinates and
distributed over an observation area, GNSSjamLoc can locate the
source of interference, even in complex propagation scenarios (e.g. urban).
It is based on a path loss physics-based model augmented with 
a data-driven component, i.e. a Neural Netrwork.
Additional information can be found at https://doi.org/10.48550/arXiv.2212.08097

---

## Repository Overview

### Problem Statement

Global Navigation Satellite Systems (GNSS), such as GPS, are critical infrastructure for positioning and navigation. However, they are vulnerable to intentional radio-frequency interference — commonly called **jamming**. A jammer is a device that broadcasts a strong radio signal on the same frequencies used by GNSS satellites, drowning out the legitimate satellite signals and preventing receivers in its vicinity from computing an accurate position fix.

**The core problem this repository addresses is:**
> Given a set of received signal power measurements collected at known spatial locations across an observation area, accurately estimate the 2D geographic position of the jamming source — even in complex, real-world environments such as urban canyons where simple free-space propagation models fail.

This is a challenging inference problem because:
- The true radio propagation in urban environments is highly non-linear (reflections, diffraction, shadowing).
- A purely physics-based model (e.g., log-distance path loss) is too simplistic and fails in complex environments.
- A purely data-driven model requires large labelled datasets and may not generalise.

---

### Data Used

The repository uses two types of data:

#### 1. Simulated Data (generated by `jammedAgentsSimulation.m`)

The MATLAB script simulates a realistic scenario:
- **Agents** (e.g., vehicles or GNSS receivers): up to 10,000 agents are placed with a uniform random distribution over a configurable observation area (default: 1 km²).
- **Jammer**: a single jamming source with a configurable transmit power (`P_jam_tx = 10 dBW`) placed at a fixed or moving location within the area.
- **Radio propagation models** (selectable):
  - Free-space path loss
  - Log-distance path loss (with exponent γ)
  - **Ray tracing** (default) — a physics-based model that accounts for reflections and diffractions, producing realistic non-line-of-sight power patterns typical of urban environments.
- **Measurement noise**: optional Gaussian noise is added to simulate real sensor imperfections.

The simulation outputs three `.mat` files (MATLAB binary format):

| File | Variable | Description |
|------|----------|-------------|
| `X.mat` | `XX` | 2D spatial coordinates (x, y in metres) of each agent's measurement location. Shape: `[N_agents × 2]` or `[N_agents × 2 × T]` for time sequences. |
| `Y.mat` | `YY` | Received power measurements (dB) at each agent location. Shape: `[N_agents]` or `[N_agents × T]`. |
| `trueJamLoc.mat` | `Jloc` | Ground-truth jammer position(s) in metres, used for evaluation. Shape: `[T × 2]`. |

A small pre-generated dataset (`X.mat`, `Y.mat`, `trueJamLoc.mat`) is included in the root of the repository so the Python estimator can be run immediately without MATLAB.

#### 2. Pre-existing Reference Data (`data/` folder)

- `data/pathloss/` — path-loss reference measurements.
- `data/raytracing/` — ray-tracing simulation outputs used for more realistic propagation modelling.
- `data/tmpMeas.mat` — temporary intermediate measurements.
- `data/matlab/` — directory where the Python code exports its results (RMSE, CRB, mean estimates) as `.mat` files for further analysis or plotting in MATLAB.

### How the Problem is Solved

GNSSjamLoc uses an **Augmented Physics-Based Model** — a hybrid approach that combines a classical signal-propagation model with a neural network. The key insight is: *use physics where it is reliable, and learn the rest from data*.

#### The Model Architecture (`model_nn.py`)

The model is a sum of two components, implemented as `Net_augmented`:

```
y_predicted(x) = f_physics(x; θ) + f_NN(x; w)
```

1. **Physics-based component — `Polynomial3` (path-loss model)**:
   - Models signal power as:  
     `P(x) = P₀ − 10·γ·log₁₀(‖x − θ‖)`  
     where `θ = (x_j, y_j)` is the **jammer position** (the parameter to be estimated), `P₀` is the transmit power, and `γ` is the path-loss exponent (default γ = 2).
   - Both `θ` and `P₀` are **learnable parameters**, so the physics model directly yields the estimated jammer location after training.

2. **Neural Network correction — `Net`**:
   - A fully connected feedforward network (default architecture: `[200 → 100 → 1]` with `tanh` activations).
   - Takes the same 2D spatial coordinates `x` as input.
   - Learns the **residual** between the true power field and the physics model prediction — capturing complex propagation effects (reflections, shadowing) that the path-loss formula cannot model.
   - An L2 regularisation term keeps the NN correction small, letting the physics model dominate when it is accurate.

The combined model is trained end-to-end using **Adam optimiser** with MSE loss.

#### Workflow — Step by Step

```
[MATLAB: jammedAgentsSimulation.m]
        │
        │  generates X.mat, Y.mat, trueJamLoc.mat
        ▼
[Python: GNSSjamLoc.py]
  1. Load data (X, Y, trueJamLoc)
  2. Split into train / test sets (default 2/3 train)
  3. Data selection: keep only the highest-power measurements
     (measurements closest to the jammer carry the most information)
  4. For each noise level (SNR sweep) and each Monte Carlo run:
       a. Optionally add Gaussian measurement noise
       b. Train the augmented model (Net_augmented) with Adam
          - Physics branch learns θ (jammer position) and P₀
          - NN branch learns the propagation residual
       c. Extract estimated jammer location from θ (learned by physics branch)
       d. Optionally refine via gradient ascent on the NN output
  5. Collect results across Monte Carlo runs:
       - Mean estimated position, variance, RMSE
       - Compare against Cramér–Rao Bound (CRB) — theoretical lower bound on estimator variance
       - Optionally compare against Maximum Likelihood Estimator (MLE) baseline
  6. Export results to data/matlab/ and save plots to figs/
```

#### Performance Evaluation

The estimator is benchmarked using:

- **RMSE** (Root Mean Square Error) of the estimated jammer position vs. ground truth.
- **CRB** (Cramér–Rao Bound): a theoretical lower bound on the variance of any unbiased estimator, computed analytically from the path-loss model and noise statistics. It serves as a gold-standard reference.
- **MLE** (Maximum Likelihood Estimator): a classical grid-search baseline that assumes a pure path-loss model.
- **CDF / PDF** of the position estimation error across Monte Carlo runs.
- Plots of estimated vs. true jammer trajectory, learning curves, and error statistics vs. SNR.

## Quick Start

### 1. Generate Data (optional — pre-generated data is included)

Open MATLAB and run:
```matlab
jammedAgentsSimulation.m
```
This produces `X.mat`, `Y.mat`, and `trueJamLoc.mat`.

### 2. Run the Estimator

```bash
python GNSSjamLoc.py
```

Key configuration options at the top of `GNSSjamLoc.py`:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `Nmc` | 20 | Number of Monte Carlo runs |
| `fixed_data_select_size` | 15 | Number of highest-power measurements used for training |
| `layer_wid` | `[200, 100, 1]` | NN layer widths |
| `epochs_init` | 200 | Training epochs |
| `lr` | 0.4 | Adam learning rate |
| `gamma` | 2 | Path-loss exponent |
| `meas_noise_var_iter` | `[10, …, 0.01]` | Noise variance sweep (SNR analysis) |

### 3. Inspect Results

Plots are saved to `figs/`. Numerical results (RMSE, CRB, mean estimates) are exported as `.mat` files to `data/matlab/`.

## jammedAgentsSimulation.m
This MATLAB program can simulate a dataset of power measurements distributed over an observation area.
Datapoints are generated with respect to jammer source characteristics, position, and dynamics.
Output data (X.mat,Y.mat, and trueJamLoc.mat) are exported and processed by the python code to estimate the jammer's location


## GNSSjamLoc.py
It estimates the jammer location from a dataset of power measurements and associated position information.


it runs over different INR, Monte Carlo, time instants
The hierarchy is :
	for each INR value
		for each MC realization
			for each time
				estimate the J. location


if time vector is > 1 but 'aggregated_over_time' is flagged, aggregated output data is computed both over MC simulations and time.
